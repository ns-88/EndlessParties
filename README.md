## 📝 Описание проекта
EndlessParties - простой сервис для организации мероприятий любого уровня: от встреч в верхах до дружеских посиделок у костра

## 🛠 Возможности API

**управление мероприятиями (Events):**

- **GET /events**: получение списка всех событий

  *Параметры фильтрации (Query string):*
    - `Title` (строка, необязательный) — поиск по названию
    - `Description` (строка, необязательный) — поиск по описанию
    - `From` (дата, необязательный) — фильтр по дате и времени начала (включительно)
    - `To` (дата, необязательный) — фильтр по дате и времени завершения (включительно)
    - `SortDirection` (число) — направление сортировки (1 - по возрастанию, 2 - по убыванию)
    - `Page` (число, необязательный) — номер страницы для пагинации (по умолчанию: `1`)
    - `PageSize` (число, необязательный) — количество элементов на странице (по умолчанию: `10`)

- **GET /events/{id}**: получение события по идентификатору
- **POST /events**: создание события
- **POST /events/{id}/book**: создание бронирования
- **PUT /events/{id}**: обновление события
- **DELETE /events/{id}**: удаление события

**управление бронированиями (Bookings):**

- **GET /bookings/{id}**: получение бронирования по идентификатору

Создание бронирования реализовано как асинхронная операция, состоящая из следующих этапов:
- при вызове метода **POST /events/{id}/book** осуществляется создание записи о новом бронировании в БД в статусе "Создана" и возврат данных (идентификатора) клиенту;
- в случае, если в событии, для которого создается указанное бронирование, отсутствуют свободные места, будет выброшено исключение ConflictException;
- идентификатор созданного бронирования добавляется в локальную очередь на обработку, реализованную на основе каналов (System.Threading.Channels), что исключает необходимость постоянного опроса БД для определения появления нового бронирования в статусе "Создана";
- при добавлении идентификатора в очередь, происходит снятие асинхронной блокировки в потоке фонового сервиса и начинается многопоточная обработка доступных в очереди бронирований с помощью метода ForEachAsync класса Parallel;
- данные бронирования запрашиваются из БД по идентификатору, обрабатываются, после чего бронирование переводится в статус "Подтверждена";
- во время обработки бронирования происходит валидация события на соответствие бизнес-правилам, если валидация заканчивается неуспешно, бронирование переходит в статус "Отклонена", а счетчик свободных мест в событии увеличен на единицу;
- в случае, если при получении события будет обнаружено, что такого события нет (например, оно было удалено), бронирование переходит в статус "Отклонена";
- фоновый поток асинхронно блокируется, ожидая новых запросов на обработку;
- после окончания процесса, клиент может получить информацию о состоянии бронирования методом **GET /bookings/{id}**
- для предотвращения перегрузки сервера, количество одновременно находящихся бронирований в очереди ограничено 1000 идентификаторов, при достижении этого числа клиенту будет возвращена ошибка при попытке создания нового бронирования.

Использованные примитивы синхронизации:
- В приложении не используются примитивы синхронизации .NET.
  Вместо них задействованы оптимистическая блокировка в обновлении события (посредством системного поля xmin) и пессимистическая блокировка на FOR NO KEY UPDATE для методов создания и обработки бронирований.

Пример овербукинга:
- Получить список событий методом **GET /events**;
- Выбрать любое из них;
- Вызвать метод **POST /events/{id}/book**, передав ему идентификатор выбранного события для получения десяти бронирований в статусе "Подтверждена";
- Вызвать метод **POST /events/{id}/book** еще один раз, что превысит количество доступных для бронирования мест;
- Клиенту будет возвращена ошибка 409 Conflict

## Миграции:
 Схема БД создается автоматически при старте приложения в режиме Development (при локальной разработке и тестировании на компьютере разработчика). Для ручного выполнения миграций выполните команду из консоли разработчика соответствующего проекта:
 ```bash
   dotnet ef database update
   ```
## Тесты:
 Тесты подразделяются на unit и интеграционные тесты и охватывают слой инфраструктуры и слой приложения.
 Интеграционные тесты реализуются библиотекой Testcontainers for .NET и запускаются в контейнерах Docker, используется образ Postgres 16-alpine.
 Docker должен быть установлен на ПК разработчика, также возможен удаленный доступ.
 Для удаленного доступа создайте файл .testcontainers.properties в домашней директории пользователя со строкой следующего вида:
 ```
 docker.host=tcp://host:2375
 ```
 Для запуска только unit тестов выполните:
 ```bash
   dotnet test --filter "Category=Unit"
   ```
 Для запуска только интеграционных тестов выполните:
 ```bash
   dotnet test --filter "Category=Integration"
   ```
 Для запуска тестов всех категорий выполните:
 ```bash
   dotnet test
   ```

## 🚀 Сборка и запуск

### Предварительные требования
- .NET 10 SDK
- IDE (Visual Studio 2026 / JetBrains Rider / VS Code)
- СУБД PostgreSQL актуальной версии

### Запуск
1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/ns-88/EndlessParties
   ```
2. Перейдите в директорию проекта:
   ```bash
   cd EndlessParties
   ```
3. Восстановите зависимости и соберите проект:
   ```bash
   dotnet build
   ```
4. Откройте файл appsettings.json и укажите адрес хоста для подключения к БД Events приложения.

5. Запустите приложение:
   ```bash
   dotnet run --project src\Presentation\EndlessParties.Presentation
   ```

После запуска Swagger-документация будет доступна по адресу: `http://localhost:5000/index.html`
