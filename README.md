## 📝 Описание проекта
EndlessParties - простой сервис для организации мероприятий любого уровня: от встреч в верхах до дружеских посиделок у костра

## 🛠 Возможности API

**управление мероприятиями (Events):**

- **GET /events**: получение списка всех событий

  *Параметры фильтрации (Query string):*
    - `Title` (строка, необязательный) — поиск по названию
    - `Description` (строка, необязательный) — поиск по описанию
    - `From` (дата, необязательный) — фильтр по дате и времени начала (включительно)
    - `To` (дата, необязательный) — фильтр по дате и времени завершения (включительно)
    - `SortDirection` (число) — направление сортировки (1 - по возрастанию, 2 - по убыванию)
    - `Page` (число, необязательный) — номер страницы для пагинации (по умолчанию: `1`)
    - `PageSize` (число, необязательный) — количество элементов на странице (по умолчанию: `10`)

- **GET /events/{id}**: получение события по идентификатору
- **POST /events**: создание события
- **POST /events/{id}/book**: создание бронирования
- **PUT /events/{id}**: обновление события
- **DELETE /events/{id}**: удаление события

**управление бронированиями (Bookings):**

- **GET /bookings/{id}**: получение бронирования по идентификатору

Создание бронирования реализовано как асинхронная операция, состоящая из следующих этапов:
- при вызове метода **POST /events/{id}/book** осуществляется создание записи о новом бронировании в БД в статусе "Создана" и возврат данных (идентификатора) клиенту;
- идентификатор созданного бронирования добавляется в локальную очередь на обработку, реализованную на основе каналов (System.Threading.Channels), что исключает необходимость постоянного опроса БД для опредления появления нового бронирования в статусе "Создана";
- при добавлении идентификатора в очередь, происходит снятие асинхронной блокировки в потоке фонового сервиса и начинается обработка бронирования;
- данные бронирования запрашиваются из БД по идентификатору, обрабатываются, после чего бронирование переводится в статус "Подтверждена";
- фоновый поток асинхронно блокируется, ожидая новых запросов на обработку;
- после окончания процесса, клиент может получить информацию о состоянии бронирования методом **GET /bookings/{id}**
- для предотвращения перегрузки сервера, количество одновременно находящихся бронирований в очереди ограничено 1000 идентификаторов, при достижении этого числа клиенту будет возвращена ошибка при попытке создания нового бронирования

## ⚠️ Формат ответа при ошибках

- **400 BadRequest**: ошибка выполнения приложения

  ```json
    {
      "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
      "title": "Ошибка выполнения приложения",
      "status": 400,
      "detail": "Ошибка получения всех событий",
      "instance": "/events",
      "traceId": "00-99d784723d66b9db814da9fd1ef0c466-4acfee88b17f56ad-00"
    }
    ```

- **500 InternalServerError**: внутренняя ошибка сервера

  ```json
    {
      "type": "https://tools.ietf.org/html/rfc9110#section-15.6.1",
      "title": "Неизвестная ошибка выполнения приложения",
      "status": 500,
      "detail": "Неизвестная ошибка",

      "traceId": "00-ab8552432b7d8d1fa39968abd9c9bf80-48c69cd853602627-00"
   }
   ```

```json
   {
     "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
     "title": "Запрашиваемый объект не найден",
   ```

## 🚀 Сборка и запуск

### Предварительные требования
- .NET 10 SDK
- IDE (Visual Studio 2026 / JetBrains Rider / VS Code)

### Запуск
1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/ns-88/EndlessParties
   ```
2. Перейдите в директорию проекта:
   ```bash
   cd EndlessParties
   ```
3. Восстановите зависимости и соберите проект:
   ```bash
   dotnet build
   ```
4. Запустите приложение:
   ```bash
   dotnet run --project src\Presentation\EndlessParties.Presentation
   ```

После запуска Swagger-документация будет доступна по адресу: `http://localhost:5000/index.html`

### Запуск тестов
```bash
   dotnet test
   ```
